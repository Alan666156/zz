# 婴儿喂养 App V1.0 契约补充（Q-01 ~ Q-18）

- 日期：2026-10-26
- 裁决：architect（经 Lead 确认）
- 适用：`docs/architecture/v1.0-baby-feeding.md` 的边界语义补充
- 结论：**接口 JSON 字段名与形状不变**；以下只锁定边界行为。与主文档冲突时以本文件为准。

## 1. 逐条裁决

| Q | 最终结论 |
|---|---|
| Q-01 CSV | `startedAt/endedAt` 保留记录原始偏移 ISO-8601；类型/侧别/单位输出中文；标签去重后按枚举定义顺序用 `\|` 连接；空值为空单元格；喂养量固定 1 位小数；CRLF + UTF-8 BOM；公式注入转义；空结果仅表头。 |
| Q-02 小数位 | 身高/头围最多 1 位小数，体重最多 2 位；三列均 `DECIMAL(5,2)`；超精度返回 400 `VALIDATION_ERROR`，不静默舍入；响应按 1/2 位 scale 输出。 |
| Q-03 标签 | 重复标签静默去重；去重后唯一标签数 ≤5；未知 code → 400；API 与 CSV 统一按枚举定义顺序输出。 |
| Q-04 PATCH babyId | PATCH 喂养记录 body 只要出现 `babyId`（含 `null`、与原值相同）→ 400 `VALIDATION_ERROR`；PATCH schema 不包含该字段。 |
| Q-05 POST 已删除 id | 一律 404 `NOT_FOUND`；不复活、不返回 tombstone。同一活跃 id 重复 POST 仍 200 `created:false`。 |
| Q-06 PATCH/GET 已删除 | 在线 `GET by id`、`PATCH` 已软删除资源 → 404；`DELETE` 已软删除 → 200 `alreadyDeleted:true`；在线接口绝不返回 tombstone。 |
| Q-07 sync tombstone | sync `DELETE` 已 tombstone → `DUPLICATE`；sync `UPSERT` 已 tombstone（任意 `baseRevision`）→ `DUPLICATE` + 当前 tombstone，永不复活，revision 不变。sync 是唯一可返回 tombstone 的入口。 |
| Q-08 sync 引用未同步宝宝 | 单条 `REJECTED`，`error.code=NOT_FOUND`；整批 HTTP 200；不泄露资源是否存在。`error` 形状为 `{code,message}`。 |
| Q-09 分页 | `size>100`、`size<1`、`page<1` → 400 `VALIDATION_ERROR`；不截断；`page` 超出总页数返回空页 200。 |
| Q-10 舍入 | `HALF_UP`；`avgAmountMl` 1 位、`avgDurationSec` 整数、`totalAmountMl/totalSolidG` 1 位；全部 BigDecimal，禁止 double。 |
| Q-11 日期边界 | 见第 2 节。 |
| Q-12 限流测试 | 新增环境覆盖：`APP_RATE_LIMIT_API_PER_MINUTE`（120）、`APP_RATE_LIMIT_INIT_PER_HOUR`（10）、`APP_RATE_LIMIT_EXPORT_PER_HOUR`（5）、`APP_RATE_LIMIT_SYNC_PER_MINUTE`（30）。E2E 每场景前 `FLUSHDB 14`，Playwright `workers: 1`；限流黑盒用例用独立低阈值测试上下文。 |
| Q-13 UUID | 所有 UUID 必须小写 canonical v4；header 非法 → 400 `DEVICE_ID_INVALID`；body/path/batchId 非法 → 400 `VALIDATION_ERROR`；不自动转小写。 |
| Q-14 data-testid | frontend-dev 在 FE-09 前提供清单并写入 `frontend/README.md`；至少覆盖 FAB、类型切换、计时控制、金额输入、保存、记录项、Tabbar、导出、离线横幅；E2E 不依赖 CSS 类名。 |
| Q-15 localStorage | 固定 key：`zz.bf.deviceId`、`zz.bf.activeBabyId`、`zz.bf.lastFeedType`、`zz.bf.syncLock`；数据丢失提示/离线横幅/导出兜底文案由 FE-07 固定并写入 README。 |
| Q-16 导出 token | TTL 固定 300 秒，不提供生产可配 TTL；测试实例注入独立 `APP_EXPORT_TOKEN_KEY`，按契约 payload/签名格式自签过期 token。 |
| Q-17 同步锁测试 | 以 BE-07 集成测试为等价证据：预先占用 `lock:sync:{deviceId}`，再调用 sync 断言 409 + `Retry-After`；覆盖重复 `batchId` 回放。 |
| Q-18 限流响应头 | `X-RateLimit-Limit`=窗口额度；`X-RateLimit-Remaining`=本次扣减后剩余（≥0），429 时为 0；429 带 `Retry-After`（秒，最小 1）；Redis fail-open 时不伪造限额头，记录告警。 |

## 2. Q-11 日期边界（最终规则）

```text
serverToday = LocalDate.now(ZoneOffset.UTC)

birthDate 合法区间：
  [serverToday.minusYears(3).minusDays(1), serverToday.plusDays(1)]   // 闭区间

measuredOn 合法区间：
  [baby.birthDate, serverToday.plusDays(1)]                            // 闭区间

说明：±1 天容差覆盖 ±14 小时时区；不新增客户端时区字段。
```

## 3. 在线 CRUD 与 sync 的 tombstone 行为矩阵

| 操作 | 活跃资源 | 已软删除 tombstone |
|---|---|---|
| `GET by id` | 200 | **404** |
| `POST` 相同 id | 200 `created:false` | **404** |
| `PATCH` | 200；revision 不匹配则 409 | **404** |
| `DELETE` | 200；revision 不匹配则 409 | 200 `alreadyDeleted:true` |
| `sync UPSERT` | 正常 APPLIED/DUPLICATE/冲突 | **DUPLICATE + 当前 tombstone** |
| `sync DELETE` | APPLIED/DUPLICATE | **DUPLICATE** |

- 在线 CRUD 绝不返回 tombstone；tombstone 只在 `sync/push` 的 `record` 中返回，供客户端覆盖本地。
- Q-05/Q-06 修正原稿“POST/GET 已删除返回 200 tombstone”的表述：测试改为 404。
- Q-07 中 UPSERT tombstone 即使 `baseRevision` 匹配也不复活，始终 `DUPLICATE`。

## 4. 导出 token canonical 格式（供测试自签）

```text
payloadPart = base64url(JSON.stringify({
  v: 1,                       // 版本
  d: "<deviceHashHex>",       // 设备 HMAC 摘要 hex
  b: "<babyId uuid>",         // 宝宝 ID
  f: "YYYY-MM-DD",            // from
  t: "YYYY-MM-DD",            // to
  e: <unixSeconds>,           // 过期时间
  n: "<uuid v4>"              // nonce
}))
signature = base64url(HMAC-SHA256(APP_EXPORT_TOKEN_KEY, payloadPart))
token = payloadPart + "." + signature
```

- base64url 不带 padding；签名对 payloadPart 的 ASCII 字节计算。
- 字段名以已实现 `ExportTokenService` 为准（短名 `v/d/b/f/t/e/n`），测试自签必须使用同一格式。
- TTL 固定 300 秒，使用代码常量，不通过配置/环境变量暴露（测试用独立 key 自签过期 token）；下载路径 `/api/v1/exports/feeding-records/{token}.csv`。
- token 只含必要过滤条件；不在日志打印 token。

## 5. 同步锁与批次幂等的 Redis key（供测试预占）

设备作用域一律使用**设备 HMAC 摘要 hex**，不使用原始设备 UUID；默认前缀 `zz:bf:v1:`（与 `APP_REDIS_KEY_PREFIX` 一致）。

```text
同步批次锁：zz:bf:v1:lock:sync:{deviceHashHex}          // SET NX PX 15s
同步批次幂等：zz:bf:v1:sync:{deviceHashHex}:{batchId}   // 24h
```

- SYNC-16 预占锁时按上述完整 key 写入；测试与后端必须使用同一 `APP_REDIS_KEY_PREFIX`。
- 释放锁用 Lua compare-and-delete；Redis 故障时跳过锁，靠数据库幂等兜底。
