### TE04-02 底部导航“首页”在非首页不可点击（UI-18 失败）

- **严重度**：P1 ｜ **归属**：frontend-dev ｜ **类型**：产品缺陷
- **用例 ID**：UI-18
- **现象**：在 `/profile` 点击 `tabbar-home` 后 URL 仍为 `/profile`，页面内容不变；
  页面快照中“首页”和“我的”同时高亮。该问题影响所有非首页 Tab（首页入口全局失效）。
- **失败断言**：`tests/e2e/profile.spec.ts:81` → `:83` 找不到 `baby-card`。
- **根因（代码定位）**：
  - `frontend/src/components/layout/TabbarLayout.vue:12`：`<van-tabbar-item replace to="/">`；
  - Vant 4 在 `route` 模式下用 `$route.matched.some(path === to)` 判断 active
    （`frontend/node_modules/vant/es/tabbar-item/TabbarItem.mjs:37-55`）；
  - 子路由的父记录 path 为 `''`（`frontend/src/router/index.ts:11`），解析后父路径为 `/`，
    因此任意页面都匹配 `to="/"` → 首页 Tab 永远 active；
  - `TabbarItem.mjs:57-62` 的 `onClick` 仅在 `!active` 时执行 `router.replace`，故点击被吞掉。
- **实测证据**（临时调试 spec，已删除）：
  - 点击前：`首页=van-tabbar-item--active`、`我的=van-tabbar-item--active`；
  - 点击后：URL 仍 `http://127.0.0.1:4173/profile`，`baby-card` 数量 0；
  - `history.length=3`，无新导航。
- **建议修复**：改为命名路由 `:to="{ name: 'home' }"`（`name` 匹配只命中首页），
  或关闭该 Tab 的 `route` 模式改为手动跳转。
- **当前状态**：源码未修复，`git log -- frontend/src/components/layout/TabbarLayout.vue` 最新仍为 FE-07。

### TE04-01 离线横幅不显示待同步条数（UI-15 / UI-16 / UI-17 失败）

- **严重度**：P1（源码已修，待复验） ｜ **归属**：frontend-dev（已修，`5b90a4a`） ｜ **类型**：产品缺陷
- **用例 ID**：UI-15（P0）、UI-16（P1）、UI-17（P0）
- **现象**：离线保存后 `offline-banner` 始终只有
  `当前离线，记录会先保存在本机，联网后自动同步`，
  不含 `（待同步 N 条）`。UI-15 要求“待同步 1 条”或等价含数字文案。
- **失败断言**：
  - `tests/e2e/offline.spec.ts:55`、`:100`、`:112`、`:122`
  - `tests/e2e/sync-conflict.spec.ts:57`
  - 实际文本：`当前离线，记录会先保存在本机，联网后自动同步`
- **根因（修复前代码，`5b90a4a` 已改）**：
  - `frontend/src/composables/useOfflineSync.ts`：`runSync()` 在 `!sync.online` 时直接 `return`，跳过了 `sync.refreshPending()`；
  - 离线写入只派发 `SYNC_REQUEST_EVENT` → `scheduleSync()` → `runSync()`，因此 `pendingCount` 一直为 0；
  - `frontend/src/stores/sync.ts` 的 `refreshPending()` 只在启动/在线同步/`finally` 中调用；
  - `OfflineBanner.vue:18` 依据 `sync.pendingCount` 生成文案，`offlineBannerOfflineText(0)` 即当前文案（`frontend/src/constants/copy.ts:18`）。
- **建议修复**：`runSync()` 先 `await sync.refreshPending()`，再判断是否在线；或离线写入入队后直接刷新 outbox 计数。
- **证据**：`tests/test-results/` 下 UI-15/16/17 的 screenshot + trace；复跑 3 条均只在该断言失败，后续同步逻辑未执行。

### TE04-04 资源型 console.error 白名单不完整（UI-01 / UI-14 / UI-19 / UI-20 失败）

- **严重度**：P2 ｜ **归属**：test-engineer ｜ **类型**：用例缺陷
- **现象**：四个用例的“页面无错误”断言失败，实际出现两类网络日志：

- **根因**：

  - `expectNoPageErrors()` 无白名单；`tests/e2e/resilience.spec.ts` 只豁免了 409 或 500 其中之一。
- **修正**：
  - `collectPageErrors()` 对 console.error 追加 `message.location().url`；
  - 新增 `KNOWN_NETWORK_ERRORS`，仅豁免 `/api/v1/babies` 的 409；
    `expectNoPageErrors(errors, allowed = KNOWN_NETWORK_ERRORS)` 默认精确豁免；
  - UI-01 去掉手写 409 过滤；UI-19 增加“stats/trend 500”白名单；UI-20 使用统一白名单；
  - **不豁免 favicon 404**：FE-02 已修复，重建 dist 后若复现即回归；
  - `tests/e2e/helpers/app.ts` 的 `OFFLINE_NETWORK_LOGS` 同步收窄：只放行 `net::ERR_*` 与已知噪音，
    不再笼统放行所有 `Failed to load resource`。
- **复跑**：UI-01、UI-14、UI-19、UI-20 在“临时豁免 favicon”的中间版本下通过；
  最终版本不豁免 favicon，需等 TE-05 重建 dist 后再确认（预计通过）。

### TE04-05 `Content-Type` 断言过严（EXP-02 失败）

- **严重度**：P2 ｜ **归属**：test-engineer ｜ **类型**：用例缺陷
- **现象**：断言 `text/csv; charset=UTF-8`，实际 `text/csv;charset=UTF-8`。
- **定性**：HTTP 允许 `;` 后可选空白（RFC 9110 OWS），Tomcat 序列化时会去掉空格；
  语义完全一致，且服务端无法稳定保留该空格。契约文档的示例写法不应被当成逐字节断言。
- **修正**：`tests/api/export.spec.ts:87` 改为 `/^text\/csv;\s*charset=UTF-8$/i`。
- **建议**：契约文档可补一句“头字段允许可选空白”，由 architect 决定，本轮未改 `docs/architecture/**`。
- **复跑**：EXP-02 通过。

### TE04-06 导出限流额度污染 EXP-09（EXP-09 失败）

- **严重度**：P2 ｜ **归属**：test-engineer ｜ **类型**：用例缺陷
- **现象**：EXP-09 在 D1 上共发 6 次 `POST /exports/feeding-records`（5 次 400 + 1 次 200），
  第 6 次返回 429。
- **事实与定性**：
  - 契约 §2.4 明确 `export` 额度为 5 次/小时/设备，且 `RateLimitInterceptor.java:74-78`
    在 Controller 之前计数，**不区分成功/失败**；因此“5 次校验 + 1 次成功”在当前契约下必然 429。
  - EXP-09 的关注点是参数校验与设备归属，不是限流；用例本身与限流额度冲突，属用例缺陷。
- **修正**：在 5 次校验后、成功请求前 `flushRedisDb()`，隔离限流计数（不改断言、不放宽 400/404 检查）。
- **复跑**：EXP-09 通过。
- **待 architect 裁决（Q-20，契约空白）**：导出限流应“所有 POST 计数”还是“仅成功签发计数”？
  当前实现与文档均为前者，建议维持；若改为后者需同步修改限流实现、文档与 RL 用例。

- **严重度**：无（源码已修） ｜ **归属**：—（TE-05 重启后复验）
- **现象**：`POST /exports/feeding-records` 响应头两条 `Cache-Control: no-store`，Playwright 合并为

### TE04-08 EXP-08 / EXP-10：错误下载返回 500 而非 404/403/410

- **严重度**：无（源码已修） ｜ **归属**：—（TE-05 重启后复验）
- **现象**：`Accept: text/csv` 请求无效/过期/已删宝宝的下载链接 → 500 空包。
- **失败断言**：`tests/api/export.spec.ts:271`（期望 404）、`:330`/`:342`（403）、`:355`（410）。
- **复核更正（重要）**：
  - 用真实 Chrome 导航头复现（`Accept: text/html,...,*/*;q=0.8`）→ **403 JSON 正常**，不会 500。
  - 仅当 `Accept` 精确为 `text/csv`（不含 `*/*`）时，旧构建在异常处理阶段协商失败 → 500。
  - 因此“真实浏览器同样 500”的说法不成立；影响面是严格只接受 CSV 的客户端。
- **源码修复**：`GlobalExceptionHandler.build()` 显式设置 `application/json;charset=UTF-8`，
  错误响应不再依赖 Accept；并新增集成测试覆盖 `text/csv` / `text/html` 两类 Accept。
- **测试侧**：保留 `Accept: text/csv` 的强断言（失败也必须是 JSON 错误包），不通过放宽请求头绕过。
- **结论**：待重启后复验，预期通过。
