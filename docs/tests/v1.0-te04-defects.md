### TE04-02 底部导航“首页”在非首页不可点击（UI-18 失败）

- **严重度**：P1 ｜ **归属**：frontend-dev ｜ **类型**：产品缺陷
- **用例 ID**：UI-18
- **现象**：在 `/profile` 点击 `tabbar-home` 后 URL 仍为 `/profile`，页面内容不变；
  页面快照中“首页”和“我的”同时高亮。该问题影响所有非首页 Tab（首页入口全局失效）。
- **失败断言**：`tests/e2e/profile.spec.ts:81` → `:83` 找不到 `baby-card`。
- **根因（代码定位）**：
  - `frontend/src/components/layout/TabbarLayout.vue:12`：`<van-tabbar-item replace to="/">`；
  - Vant 4 在 `route` 模式下用 `$route.matched.some(path === to)` 判断 active
    （`frontend/node_modules/vant/es/tabbar-item/TabbarItem.mjs:37-55`）；
  - 子路由的父记录 path 为 `''`（`frontend/src/router/index.ts:11`），解析后父路径为 `/`，
    因此任意页面都匹配 `to="/"` → 首页 Tab 永远 active；
  - `TabbarItem.mjs:57-62` 的 `onClick` 仅在 `!active` 时执行 `router.replace`，故点击被吞掉。
- **实测证据**（临时调试 spec，已删除）：
  - 点击前：`首页=van-tabbar-item--active`、`我的=van-tabbar-item--active`；
  - 点击后：URL 仍 `http://127.0.0.1:4173/profile`，`baby-card` 数量 0；
  - `history.length=3`，无新导航。
- **建议修复**：改为命名路由 `:to="{ name: 'home' }"`（`name` 匹配只命中首页），
  或关闭该 Tab 的 `route` 模式改为手动跳转。
- **当前状态**：已修复（FE-10 改用命名路由匹配）；2026-10-26 fresh build 复验 `npx playwright test e2e/profile.spec.ts -g "UI-18"` → **1 passed**。

  - 离线访问**从未下载**的 route chunk 不属于 V1.0 功能范围，不要求离线加载成功；

    - 标题“页面加载失败”；

    - `data-testid="route-load-error"`、`data-testid="route-load-retry"`，按钮“重试/取消”；
    - 失败时当前路由（URL）保持不变；仅手动重试；再次失败时对话框重新出现；
  - P2 idle prefetch 可选，不作为验收门槛；UI-16 不得依赖 prefetch。
- **FE-11 修复与复验（2026-10-26）**：

  - Q-24 §7.4 明确“P1 判定以对话框出现为准，而不是控制台日志”。该场景本身会产生一条
    `pageerror: Unable to preload CSS for …`，因此 UI-22 **不执行** `expectNoPageErrors`；其他 E2E 仍按 Q-23 严格判定（`pageerror` 与资源型 console.error 以外的错误均失败）。
- **当前状态**：**已修复并复验 PASS**。若后续要求“该预期 chunk 失败连 pageerror 也不得产生”，需单独派修并重新确认 Q-23 与 Q-24 §7.4 的优先级；当前按 Q-24 §7.4 以对话框为验收依据。

### TE04-11 删除未同步的离线新建记录后，待同步计数不归零（UI-16 附带发现）

- **严重度**：P2 ｜ **归属**：frontend-dev ｜ **类型**：产品缺陷（提示计数）

- **复现步骤**：

  4. 列表只剩种子记录，outbox 已撤销该条，但横幅仍显示“待同步 1 条”。

### TE04-05 `Content-Type` 断言过严（EXP-02 失败）

- **严重度**：P2 ｜ **归属**：test-engineer ｜ **类型**：用例缺陷
- **现象**：断言 `text/csv; charset=UTF-8`，实际 `text/csv;charset=UTF-8`。
- **定性**：HTTP 允许 `;` 后可选空白（RFC 9110 OWS），Tomcat 序列化时会去掉空格；
  语义完全一致，且服务端无法稳定保留该空格。契约文档的示例写法不应被当成逐字节断言。
- **修正**：`tests/api/export.spec.ts:87` 改为 `/^text\/csv;\s*charset=UTF-8$/i`。
- **建议**：契约文档可补一句“头字段允许可选空白”，由 architect 决定，本轮未改 `docs/architecture/**`。
- **复跑**：EXP-02 通过。

### TE04-06 导出限流额度污染 EXP-09（EXP-09 失败）

- **严重度**：P2 ｜ **归属**：test-engineer ｜ **类型**：用例缺陷
- **现象**：EXP-09 在 D1 上共发 6 次 `POST /exports/feeding-records`（5 次 400 + 1 次 200），
  第 6 次返回 429。
- **事实与定性**：
  - 契约 §2.4 明确 `export` 额度为 5 次/小时/设备，且 `RateLimitInterceptor.java:74-78`
    在 Controller 之前计数，**不区分成功/失败**；因此“5 次校验 + 1 次成功”在当前契约下必然 429。
  - EXP-09 的关注点是参数校验与设备归属，不是限流；用例本身与限流额度冲突，属用例缺陷。
- **修正**：在 5 次校验后、成功请求前 `flushRedisDb()`，隔离限流计数（不改断言、不放宽 400/404 检查）。
- **复跑**：EXP-09 通过。
- **待 architect 裁决（Q-20，契约空白）**：导出限流应“所有 POST 计数”还是“仅成功签发计数”？
  当前实现与文档均为前者，建议维持；若改为后者需同步修改限流实现、文档与 RL 用例。

- **现象**：`Accept: text/csv` 请求无效/过期/已删宝宝的下载链接 → 500 空包。
- **失败断言**：`tests/api/export.spec.ts:271`（期望 404）、`:330`/`:342`（403）、`:355`（410）。
